# Paper Evidence Map v0.2.0 — adaptive, goal-directed paper reading

Paper Evidence Map v0.2.0 replaces the fixed deep-read entry point with minimum-sufficient, goal-directed reading while preserving evidence localization, claim boundaries, and source isolation.

## Added

- Five adaptive reading depths: Scan, Triage, Targeted, Deep, and Audit.
- Goal-driven lenses for relevance, contribution, method, experiments, evidence, critical review, gaps, ideas, learning, and presentations.
- A thin Skill router with declarative static and on-demand loading.
- Candidate Issue, Candidate Gap, and Candidate Idea controls that keep paper-internal support separate from external novelty.
- Multi-paper session controls: Session Goal, Active Paper, Paper Set, explicit Comparison Set, and paper-internal evidence isolation.
- Adaptive-routing fixtures, failure classes, evaluation guidance, and deterministic CI checks.

## Changed

- Unspecified paper-reading requests now route to Triage rather than an automatic full evidence map.
- Open requests such as “take a look” must complete the Triage core instead of falling back to Scan.
- Stable reading goals carry across turns in the same chat.
- Reading value is goal-relative; unknown personalized relevance remains `cannot judge` instead of being guessed.
- Cross-table comparisons bind model/version, dataset/split, input or track source, evaluation setting, and experimental purpose.
- `Round 1` and `Round 2` remain backward-compatible shortcuts for Deep and Audit.
- Full and compact English and Simplified Chinese Project instructions share the same adaptive behavior contract.

## Evidence and safety boundaries

- Paper facts and author interpretations must remain bound to their primary paper and official supplements.
- External information cannot fill evidence the active paper did not report.
- Cross-paper synthesis is allowed only when the user explicitly requests comparison or synthesis, with source attribution retained.
- A paper or paper set cannot establish field-level novelty without an actual external literature search.

## Validation

- Repository validation and 23 regression tests pass on Python 3.9 and 3.13.
- Synthetic Markdown and JSON fixtures retain all eight planted evidence findings.
- The adaptive-routing fixture checks seven core cases, four cross-case invariants, and eight failure classes.
- Deterministic checks validate repository and fixture contracts; they do not guarantee identical semantic behavior across models, modes, or repeated runs.

## Known limitations

- Model outputs remain stochastic, and lower-effort modes may require clearer task wording for consistent routing.
- PDF extraction and attachment selection partly depend on the host product environment.
- Multi-paper controls provide source isolation and explicit comparison scope; they are not a full systematic-review workflow.
- Field-wide novelty and literature completeness still require external search and a documented review scope.

## Upgrade

Replace the previous Project instructions with the v0.2.0 full or compact English/Chinese prompt. Start a fresh chat for clean evaluation, upload the paper, and state the reading goal when you want a goal-conditioned Triage extension such as idea finding, presentation preparation, or benchmark selection.
