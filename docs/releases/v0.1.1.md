# Paper Evidence Map v0.1.1 — safer sources and stronger verification

This release keeps the copy-paste workflow while turning post-release findings into explicit safeguards and reproducible tests.

## Added

- Full and compact English and Simplified Chinese Project instructions exposed in the quickstart.
- Current-chat attachment precedence, a recovery trigger, and a manual cross-chat/Project contamination fixture.
- Adversarial multi-file and access-limit fixtures for source isolation, document prompt injection, and evidence-aware refusal.
- A representative JSON export and stronger evidence-map Schema invariants.
- A deterministic synthetic PDF builder and 20 validator regression tests.
- A ready-to-upload 1280×640 GitHub social preview.

## Changed

- The validator now separates repository integrity, generic response structure, synthetic content assertions, JSON validation, and PDF checks.
- Structural scoring resists keyword stuffing, partial support-label matches, fabricated locators, and input papers masquerading as answers.
- CI retains the branch-protection check name `repository` on Python 3.13 and adds a separate Python 3.9 compatibility job.
- README and evaluation docs distinguish deterministic fixture checks from live model evidence.

## Known limitations

- Attachment selection depends partly on the ChatGPT product environment; repeat the current-chat precedence fixture before calling the issue fixed.
- Full evidence maps can be long. The compact prompt reduces scope but does not guarantee a particular response length.
- The automated checker validates structure and planted fixture findings, not universal scientific correctness.

## Upgrade

Replace the Project instructions with the v0.1.1 full or compact prompt, start a fresh chat, upload the paper, and verify that the source ledger names that current-chat upload as S1 before relying on the analysis.
