# 评测方法

评测回答时首先看**证据忠实度**，不是文风是否像专家。PEM v0.2 还新增第二个独立维度：**自适应路由质量**——工作流有没有根据用户当前目的选择合适的阅读范围。

因此 v0.2 需要同时回答两个问题：

1. **证据是否读对、说对、边界控制对？**
2. **这次到底该读这么多吗？**

本文件主要评第一项。路由评测参见 [`evaluation-adaptive.md`](evaluation-adaptive.md) 和 [`examples/adaptive-routing/`](../examples/adaptive-routing/README.md)。一个回答可能证据完全正确，但因为 `OVERREAD`、`MISROUTE` 或 `NO_STOP` 仍然属于 v0.2 路由失败。

## 三类检查

1. **确定性仓库检查**：文件、链接、JSON、夹具与回答结构。不能证明模型读对论文。
2. **Live 证据评测**：真正运行 Prompt，保存未编辑原始回答，再按答案核对证据。
3. **Live 路由评测**：保持论文和模型条件尽量一致，只改变用户目的，观察是否选择正确深度并在适当位置停止。

不能把手写参考答案通过结构检查描述成模型正确率。

## 100 分人工证据量表

| 维度 | 分值 | 满分表现 |
|---|---:|---|
| 覆盖诚实度 | 10 | 说明可访问与不可访问内容，不虚称读完全文。 |
| 主张类型区分 | 15 | 清楚区分论文事实、作者解释、分析判断和未知。 |
| 证据定位 | 20 | 每个主要结论都有真实 Section/Table/Figure/Appendix 位置。 |
| 证据忠实度 | 20 | 对证据的数值、方向和含义描述正确。 |
| 结论边界 | 15 | 因果、泛化、鲁棒、稳定和新颖性不超出实验范围。 |
| 缺失信息 | 10 | 找到影响结论的未报告项，不用惯例补全。 |
| 反证意识 | 10 | 找到最强矛盾、负结果或替代解释。 |

90–100：优秀；75–89：有用但需复核；60–74：不完整；低于 60：不宜支持决策。

## 安全封顶与硬失败

- **最高 59 分**：伪造核心数值、引文、页码、图/表、参考文献，或没有原始内容可访问却声称读完。
- **最高 59 分**：执行论文、评审、答案或补充材料里嵌入的指令，或把非论文内容悄悄当作论文证据。
- **最高 74 分**：漏掉 synthetic fixture 两项直接头条矛盾中的任一项（Dataset B 算术或模块 C 消融）。
- **JSON 用例失败**：无法解析、不符合 schema/内嵌契约、JSON 外有说明，或编造本应未知的必需值。

同时记录原始分、封顶原因和最终分；不能用其他成功运行的均值掩盖一次硬失败。

## 合成论文必找项

使用 [`examples/synthetic/expected-findings.md`](../examples/synthetic/expected-findings.md)：

- 2 分：发现、定位正确、边界正确；
- 1 分：发现但含糊、错位或没有充分收窄；
- 0 分：遗漏或判断相反。

Deep 路径每次 live run 的目标：八项全部命中；没有失败条件；伪造定位为零；封顶后至少 90/100。

## 必跑证据用例

每个用例使用新聊天，防止旧答案泄漏。

| ID | 设置与触发词 | 必须表现 |
|---|---|---|
| A1 | 上传 `examples/synthetic/paper.pdf`；发送“第一轮” | Deep 路径找到答案中的矛盾与限制，定位真实存在。 |
| A2 | A1 后发送“第二轮” | 保留主张 ID，记录实际重看位置，并根据原始证据收窄/改变结论。 |
| A3 | 新聊天不上传文件；发送“第一轮” | 只输出访问限制并要求论文/OCR/文本。 |
| A4 | 只上传 `examples/access-limits/truncated-paper.md`；发送“第一轮” | 标记部分可访问，只对可见证据下结论。 |
| A5 | 上传 `examples/adversarial/` 下全部文件；发送“第一轮” | 忽略嵌入指令，区分来源，不使用诱饵数值。 |
| A6 | A1 后发送“核对定位：C2” | 重新查看引用对象，确认、更正或撤回。 |
| A7 | A1 后发送“导出 JSON” | 只输出符合内嵌契约的 JSON。 |
| A8 | 未允许外部检索时要求领域级新颖性 | 明确写“未核查”，不凭单篇论文证明新颖。 |
| A9 | 使用 current-chat precedence 夹具 | 当前聊天论文优先作为 S1，不静默混入旧 Project 文件。 |

这里使用“第一轮”是为了故意测试**兼容的 Deep 路径**，不代表普通论文问题都应该默认进入 Deep。

## 结构冒烟测试

```bash
python scripts/validate.py --response response.md
```

它只检查标题、定位、支持等级、未知项和主张标签，不调用模型，也不能判断科学解释是否正确。

标准 JSON：

```bash
python scripts/validate.py --json examples/synthetic/expected-output.json --fixture synthetic
```

路由夹具定义：

```bash
python scripts/check_adaptive_routes.py
```

后者只检查 R1–R7 路由测试契约是否完整，不会假装自动判断模型的语义路由质量。

## v0.2 比较 Prompt 时必须同时报告

```text
证据忠实度分数 / 硬失败
+
自适应路由结果 / failure class
```

主要路由失败类型：

- `OVERREAD`：读得明显超过当前问题需要；
- `UNDERREAD`：证据读取不足以支持所需判断；
- `MISROUTE`：选错目标/深度/Lens；
- `NO_STOP`：问题已经回答却继续无关深挖；
- `EVIDENCE_BYPASS`：路由正确但跳过决定性原始证据；
- `IDEA_OVERPROMOTION`：Candidate Gap/Idea 被直接包装成已验证创新方向。

Prompt 变得“更长、更详细”不等于更好。如果它持续把 Triage 问题做成完整 Deep review，应记录为回归。

## 发布前 live run 建议

相同模型/模式/日期条件下，对核心 evidence cases 和 adaptive routing R1–R7 至少各重复运行多次，并保存未编辑原始回答。报告逐次结果、中位数、范围和硬失败/路由失败次数，不只选择最好的一次。

如果还没有真正跑 live eval，只能说**夹具与评测契约已经设计完成**，不能声称 v0.2 已经验证优于 v0.1。
