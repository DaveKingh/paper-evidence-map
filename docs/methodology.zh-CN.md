# 方法说明

## 核心对象：主张—证据—边界

对每个影响结论的主张，工作流追问三个问题：

1. **主张**：究竟声称了什么，是论文事实、作者解释还是助手判断？
2. **证据**：哪项结果或方法细节与它相关，具体在哪里？
3. **边界**：现有证据能够辩护的最强但更窄的表述是什么？

第三问很关键：找到正确表格，不代表可以重复一个比表格范围更大的结论。

## 为什么分两轮

第一轮优化覆盖，重建论文并暴露断裂链路；第二轮优化证伪，重新查看最关键证据，寻找替代解释，并主动收窄结论。分开执行可以降低“一次长回答看起来很深入、实际没有重查关键证据”的风险。

## 四类标签

| 标签 | 含义 | 示例 |
|---|---|---|
| 论文事实 | 原文明确报告且可定位 | “Table 2 报告 macro-F1 为 0.78。” |
| 作者解释 | 作者的解释、因果归因或推广 | “作者把提升归因于模块 G。” |
| 分析判断 | 基于论文内部证据的判断 | “消融结果削弱了‘模块必需’主张。” |
| 未知 | 没写或无法访问 | “随机种子数量未说明。” |

标签描述命题内容，而不是“这句话能否在论文中找到”。“Table 2 报告 0.78”是论文事实；“这证明模块必不可少”若来自作者，仍是作者解释，即使原句可以定位。观察和推断混在一句话中时应拆开。

## 支持强度

- **强**：直接证据、对照与不确定性报告都与结论范围匹配。
- **中等**：有相关证据，但仍有一项实质限制。
- **弱**：证据间接、范围窄、对照不足，或与主张宽度不一致。
- **无法判断**：决定性信息缺失或不可访问。

强度针对单个主张，不是论文总分。

“弱”和“无法判断”有意区分：能看到与主张相关但间接、错配、对照不足或矛盾的证据时用**弱**；决定性证据缺失或无法访问时用**无法判断**。这样不会把“没读到”误写成反面证据。

## 访问与来源门

出现附件图标不等于内容已经读取。输出实质结论前，工作流要记录：

- 哪些文件是主论文、补充材料或非论文背景；
- 哪些章节和证据对象已经检查；
- 文件中哪些内容存在但未检查；
- 哪些内容缺失、不可读、被截断或 OCR 不确定。

若没有可检查的实质性原始论文内容，正确结果是“访问限制”，而不是根据标题或先前答案填出半张证据地图。只有部分可访问时，结论必须留在可见范围内。

多文件场景用稳定来源编号，防止在论文、补充材料、评审和答案之间“洗证据”。定位应同时标出来源和证据对象，如“S1，Table 2，without C 行”。只有文档中可见的印刷页码才能直接称页码；查看器页码必须标注。正文写“见 Figure 4”并不能证明提供的材料中真的有 Figure 4，更不能证明已经检查。

在 Project 中，“文件可用”不等于“本次应选它”。当前聊天里最新上传且可访问的论文，必须优先作为主来源 `S1` 候选，不能被较早的 Project 文件或历史分析替代；若当前聊天同时有多篇候选论文，则先请用户指定。本仓库用[人工回归夹具](../examples/current-chat-precedence/README.md)覆盖这种产品依赖行为，并在[已知问题](known-issues.md#项目中的旧文件被错误选为主论文)中提供恢复方法。

这道访问门与当前 [ChatGPT Projects 官方文档](https://learn.chatgpt.com/docs/projects)描述的机制一致：项目可以让多个聊天共享已上传文件和项目指令，但任务所需来源仍要上传或连接。产品界面与限制会变化，因此本仓库提供完整版和精简版指令，但不声称未公开的固定字符上限。

## 主张级支持判定

依次追问：

1. 决定性证据可访问吗？不能则为**无法判断**。
2. 引用对象里真的有该数值、方向和比较吗？没有就撤回/更正定位；若看到矛盾证据，该主张通常为**弱**。
3. 设计是否匹配主张的具体人群、任务、干预、基线、指标和时间范围？
4. 对照和不确定性是否足以支持该范围？
5. 最强且更窄的可辩护表述是什么？

同一数值可以强力支持“论文报告 X”这项描述事实，却只能很弱地支持作者据此提出的因果或普遍结论。支持强度取决于被评估的具体措辞。

## 能防什么，不能防什么

它重点防止摘要/结论过度表述、事实与解释混淆、用惯例填补缺失信息、单条件外推、无消融的“关键模块”、跨章节数字矛盾、PDF 内提示注入，以及虚假的“已读全文”表述。

它也明确防止论文、补充材料、评审和答案之间的来源混合，以及伪造页码、图号、数值、引文或参考文献。

它还要求阻止 Project 中的旧论文在未说明的情况下替换当前聊天刚上传的论文。

它不能自动识别伪造原始数据、所有统计错误或无法读取的内容；没有外部文献证据时，也不能证明领域级新颖性。

## Prompt 版本与功能边界

- `project-instructions.md` 是完整契约，包含两轮流程、来源控制、定位复核、外部新颖性检索边界、论文比较和自包含 JSON 导出。
- `project-instructions-compact.md` 用更短篇幅保留第一轮/第二轮最关键的证据控制，有意省略 JSON 和专门触发词。

任何 Prompt 都不能保证模型服从。它只是可测试工作流的一部分：先用答案已知的夹具，按内容而不是文风打分，人工打开每个引用位置，并在记录模型/模式/日期的条件下重复运行。

## 为什么 JSON 契约要内嵌

用户可能只复制 Project 指令，而没有把仓库 schema 上传给模型。因此完整版 Prompt 内嵌了“导出 JSON”的必需字段与枚举。模型能访问 schema 时仍以 schema 为机器校验标准；不能访问时则按内嵌契约输出。未知值使用 `null` 或空数组，不靠猜测补全。
