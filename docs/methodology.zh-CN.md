# 方法说明

## 核心对象：主张—证据—边界

对每个影响结论的主张，工作流追问三个问题：

1. **主张**：究竟声称了什么，是论文事实、作者解释还是助手判断？
2. **证据**：哪项结果或方法细节与它相关，具体在哪里？
3. **边界**：现有证据能够辩护的最强但更窄的表述是什么？

第三问很关键：找到正确表格，不代表可以重复一个比表格范围更大的结论。

## 先决定“需要读多深”

Paper Evidence Map 不再假设每篇论文第一次接触时都应该建立完整证据地图。它先判断用户当前为什么读这篇论文，再选择能够可靠回答问题的最小阅读深度。

用户只上传论文但没有要求全文深读时，默认使用 **Triage**，而不是 Deep。

| 深度 | 目的 |
|---|---|
| Scan | 判断论文大致在做什么 |
| Triage | 判断相关性、阅读价值，以及下一步该看哪里 |
| Targeted | 回答一个具体方法、实验、主张或 Idea 问题 |
| Deep | 建立较完整的方法/实验/主张—证据地图 |
| Audit | 重新打开决定性证据，尝试证伪或收窄关键结论 |

只有当前深度无法支撑用户所需结论时才升级。当前问题已经用足够证据和不确定性说明回答后，应停止，而不是自动继续生成更多栏目。

## 第一轮和第二轮现在处于什么位置

原来的两轮流程仍然有价值，但现在它是 **Deep → Audit** 的一种路径，而不是所有论文阅读的统一入口。

- **第一轮 / Round 1** 对应 Deep：系统重建论文、暴露断裂链路并建立较完整的主张—证据地图。
- **第二轮 / Round 2** 对应 Audit：重新查看最重要证据，寻找反证和替代解释，并在必要时收窄或撤回结论。

两轮分开执行仍然可以降低“一次长回答看起来很深入、实际没有重查关键证据”的风险。v0.2 的变化是：大量真实科研阅读问题应该在 Triage 或 Targeted 阶段就停止。

## 四类标签

| 标签 | 含义 | 示例 |
|---|---|---|
| 论文事实 | 原文明确报告且可定位 | “Table 2 报告 macro-F1 为 0.78。” |
| 作者解释 | 作者的解释、因果归因或推广 | “作者把提升归因于模块 G。” |
| 分析判断 | 基于论文内部证据的判断 | “消融结果削弱了‘模块必需’主张。” |
| 未知 | 没写或无法访问 | “随机种子数量未说明。” |

标签描述命题内容，而不是“这句话能否在论文中找到”。“Table 2 报告 0.78”是论文事实；“这证明模块必不可少”若来自作者，仍是作者解释，即使原句可以定位。观察和推断混在一句话中时应拆开。

## 支持强度

- **强**：直接证据、对照与不确定性报告都与结论范围匹配。
- **中等**：有相关证据，但仍有一项实质限制。
- **弱**：证据间接、范围窄、对照不足，或与主张宽度不一致。
- **无法判断**：决定性信息缺失或不可访问。

强度针对单个主张，不是论文总分。“弱”表示能看到相关证据，但它间接、错配或不足；“无法判断”表示决定性证据缺失或不可访问。

## 访问与来源门

出现附件图标不等于内容已经读取。输出实质结论前，工作流需要建立与当前阅读深度相匹配的来源/访问状态：

- 哪些文件是主论文、补充材料或非论文背景；
- 哪些章节和证据对象已经检查；
- 当这一区分会影响结论时，哪些内容存在但未检查；
- 哪些内容缺失、不可读、被截断或 OCR 不确定。

这道门会随深度缩放。Triage 不需要为了形式做整篇论文的完整覆盖清单，但必须披露会改变当前判断的关键缺失。Deep/Audit 则需要更广泛的来源与覆盖登记。

若没有可检查的实质性原始论文内容，正确结果是“访问限制”，而不是根据标题、文件名、记忆或先前答案填出分析。

多文件场景使用稳定来源编号，防止论文、补充材料、评审和答案之间“洗证据”。定位应同时标出来源和证据对象，如“S1，Table 2，without C 行”。只有文档中可见的印刷页码才能直接称页码；查看器页码必须标注。

在 Project 中，“文件可用”不等于“本次应选它”。当前聊天里最新上传且可访问的论文，必须优先作为主来源 `S1` 候选，不能被较早的 Project 文件或历史分析替代；若当前聊天同时有多篇候选论文，则先请用户指定。本仓库用[人工回归夹具](../examples/current-chat-precedence/README.md)覆盖这种产品依赖行为，并在[已知问题](known-issues.md#项目中的旧文件被错误选为主论文)中提供恢复方法。

## 主张级支持判定

依次追问：

1. 决定性证据可访问吗？不能则为**无法判断**。
2. 引用对象里真的有该数值、方向和比较吗？没有就撤回/更正定位；若看到矛盾证据，该主张通常为**弱**。
3. 设计是否匹配主张的具体人群、任务、干预、基线、指标和时间范围？
4. 对照和不确定性是否足以支持该范围？
5. 最强且更窄的可辩护表述是什么？

同一数值可以强力支持“论文报告 X”这项描述事实，却只能很弱地支持作者据此提出的因果或普遍结论。支持强度取决于被评估的具体措辞。

## Candidate Gap 与 Research Idea

PEM 可以在完整审计之前发现有价值的研究杠杆，但必须保守标注状态。

论文内部的异常或缺失，只有在具体且能追溯到论文证据时，才登记为 **Candidate Gap**。作者没有做某个实验，并不自动等于一个可发表 Research Gap。

**Candidate Idea** 至少保留以下链条：

`观察 → Candidate Gap → 研究问题 → 假设 → 最小实验 → 可能贡献 → 风险`

只有在 Targeted Evidence Check 足以确认这个 gap 确实存在，并在必要时完成外部新颖性和可行性核查后，才能升级成更强的 Research Idea。这就是：**没有验证过的 Gap，就不下强 Research Idea。**

## 能防什么，不能防什么

它重点防止：

- 摘要/结论过度表述；
- 事实与解释混淆；
- 用领域惯例填补论文未报告信息；
- 单条件外推；
- 无消融的“关键模块”主张；
- 跨章节数字矛盾；
- PDF 内提示注入；
- 论文、补充材料、评审和答案之间的来源混合；
- Project 中旧论文无提示地替换当前聊天新论文；
- 伪造页码、图号、数值、引文或参考文献；
- 虚假的“已读全文”；
- **过度阅读（OVERREAD）**：用户只需要窄问题，却自动输出完整审计；
- **Idea 过度升级（IDEA_OVERPROMOTION）**：把早期异常直接包装成已验证创新方向。

它不能自动识别伪造原始数据、所有统计错误或无法读取的内容；没有外部文献证据时，也不能证明领域级新颖性。

## Prompt 版本与功能边界

- `project-instructions.md` 是完整自适应契约，包含目的/深度路由、来源控制、Deep/Audit 兼容、Gap/Idea 状态、定位复核、外部新颖性边界、比较和自包含 JSON 导出。
- `project-instructions-compact.md` 用更短篇幅保留自适应路由和最关键的证据控制，有意省略 JSON 导出与专门触发词。

任何 Prompt 都不能保证模型服从。它只是可测试工作流的一部分：使用答案已知的夹具，不只评“内容对不对”，还评“有没有正确选择阅读深度”，人工打开关键引用位置，并在记录模型/模式/日期的条件下重复运行。

## 为什么 JSON 契约要内嵌

用户可能只复制 Project 指令，而没有把仓库 schema 上传给模型。因此完整版 Prompt 内嵌了“导出 JSON”的必需字段与枚举。模型能访问 schema 时仍以 schema 为机器校验标准；不能访问时则按内嵌契约输出。未知值使用 `null` 或空数组，不靠猜测补全。
